## `resetKey(key)`

Resets the rate limiting for a given key. An example use case is to allow users
to complete a captcha to reset their rate limit, then call this function.

Example:

```ts
import { rateLimit, ipKeyGenerator } from 'express-rate-limit'

const limiter = rateLimit({
    skip: (req) => req.url === '/reset', // Don't limit the reset url!
	// ...
})

app.use(limiter)

app.post('/reset', async (req, res) => {
    if (/* Validate that they completed the captcha or whatever */) {
        limiter.resetKey(ipKeyGenerator(req.ip));
        res.send('Rate limit is reset!')
    } else {
        res.status(400).send("Wrong answer, try again.")
    }
})
```

The default [`keyGenerator`](/reference/configuration#keygenerator) stores IPv6
clients under their [subnet](/reference/configuration#ipv6subnet) rather than
their full address, so `resetKey(req.ip)` would not match their key. Passing the
IP through [`ipKeyGenerator`](/reference/helpers#ipkeygenerator) produces the
same key the limiter uses (pass your `ipv6Subnet` as the second argument if you
changed it). If you use a custom `keyGenerator`, pass the key it returns
instead.

## `getKey(key)`

Retrieves the hit count and reset time from the store for a given key.

Note: `getKey` depends on store support. It works with the MemoryStore and
cluster-memory-store, but may not work with other stores. Calling it will throw
an error if the store does not have a `get` method.

## `shutdown()`

Shuts down the middleware's store, stopping its timers and releasing the
resources it holds (for the default MemoryStore, that is the window-reset
interval and the hit-count maps). Returns a promise that resolves once the store
has been shut down.

Call this when the limiter is no longer needed — for example when retiring an
old instance during a rolling restart, or at the end of a test run — so the
store's resources do not linger for the lifetime of the process:

```ts
const limiter = rateLimit({
	// ...
})

app.use(limiter)

// Later, when the limiter is being torn down:
await limiter.shutdown()
```

The method is idempotent: only the first call performs the shutdown, and
subsequent calls return the same promise.

Note: `shutdown` depends on store support. If the configured store does not
implement a `shutdown` method, a warning is logged and the returned promise
resolves without doing anything.
